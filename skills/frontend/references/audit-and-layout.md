# 页面理解、审计与布局

## 任务与证据

确定用户进入页面的任务、所需输入、完成结果、页面范围和当前交付阶段。记录用户要求保留的组件、业务规则、文字、位置与交互。当前有效请求和最新文件决定后续操作。

沿一个实际操作定位现有实现：

1. HTML 或组件中的页面区域、控件、`id` 和 class。
2. 事件绑定、处理函数和页面状态。
3. 请求地址、参数、返回字段、数据含义和保存行为。
4. 结果渲染、条件显示和相关 CSS。
5. 后端接口、已有测试和实际运行结果。

异步功能还需理解请求取消、结果有效性和页面切换。盘点默认内容、条件内容、展开内容和弹窗。分别记录代码能够证明的结构事实、实际运行观察以及尚待验证的布局推断。

产物是完整的元素与操作清单，以及元素、事件、请求、状态和显示结果之间的对应关系。无法访问账户或取得数据时，明确说明证据覆盖的部分。

## 信息架构审计

逐项记录元素名称、显示条件、支持的任务、当前位置、操作及处理理由。问题分为：

- 信息数量：默认内容、重复信息和同时展示的任务。
- 视觉层级：主要结果、核心操作与辅助内容的强调程度。
- 空间布局：宽度、留白、图表面积、换行、遮挡与窄屏内容长度。
- 操作复杂度：入口、步骤、核对、保存与返回路径。

元素处理建议使用以下含义：

- 保留：在相应任务与状态中直接展示。
- 降级：保留内容，减少视觉强调或移到辅助位置。
- 折叠：通过清楚的入口按需查看，或进入专门页面。
- 建议删除：明确重复内容或缺少任务价值的证据与影响范围。

无法确定的功能去留、页面归属或数据含义标记为待决策，说明已有证据、需要确定的事项和影响。业务能力与页面展示分别核查，正式删除依据用户决定与授权进行。

审计交付完整元素清单、任务价值、四类问题、处理建议、理由和待决策事项。只读审计结束于所要求的分析交付。

## 信息层级和状态设计

围绕当前任务设计：

- 没有数据：清楚说明需要输入什么，突出主要入口。
- 输入或导入：呈现输入区域、处理状态及必要提示。
- 核对：提供完整字段、异常提示、修改与确认操作。
- 查看结果：优先展示结论、关键图形和必要指标。
- 查看详情：通过明确入口访问依据、记录、参数和进一步分析。
- 修改资料：提供清楚的编辑、核对、保存与返回流程。

主要操作和结果获得清楚的视觉中心。低频工具集中到适用的辅助入口，展开内容保持核心区域可用。相关页面使用共同导航和相同类型的交互规则。

保留用户认可的组件和业务规则，复用现有图表、表单、导航和数据处理。说明每个模块的位置与任务关系，包括默认状态、展开、侧栏收起、弹窗、键盘和焦点行为。

普通界面使用清楚的标签、状态和操作文字。重复说明与防御性文案按照审计结果处理，当前错误、数据来源和状态在相应任务位置呈现。通常提供一个完整设计；需要决定的事项说明成立的选择及影响。

产物是模块位置、信息主次、状态和交互设计。设计应覆盖相关状态与完整操作能力。

## ASCII 文本框草图

在制作新的 HTML Demo 前，先在会话中交付 ASCII 文本框草图。已有草图与当前目标布局一致且已经交付时，可以直接使用。

草图清楚表达：

- 导航、侧栏、主区域和辅助区域的位置关系。
- 核心操作、主要结论、图形和辅助信息的层级。
- 按钮、菜单、导入、编辑和详情入口。
- 默认展示、按需展开和独立页面的关系。
- 对布局有影响的无数据、有结果、侧栏收起和详情展开等状态。

使用简短界面文字、文本框边界和清楚的操作标记。需要多个状态草图时分别呈现。模块位置说明解释其任务价值。

用户提出调整时更新草图。用户明确要求先查看草图时，交付后等待反馈；已有授权覆盖后续制作时，根据当前确定的草图继续。

## 可运行 HTML Demo

输入是已交付的当前 ASCII 草图、设计要求和制作预览授权。创建文件前确认写入范围与 Git 忽略规则，使用项目内已被忽略的工作目录；默认目录为 `.janus-work/frontend/`。

Demo 需要能够打开并操作，覆盖设计中关键状态和交互，例如导入前后、详情展开、问卷填写与返回、侧栏收起、弹窗关闭和不同宽度下的显示。

使用真实项目标签、现有内容和已取得的数据；数据暂不可用的位置保持清楚的空白状态。需要已有图表、组件或依赖时，采用项目的必要依赖与既有运行方式。说明数据来源、可操作内容、保存行为和接口连接情况。

需要查看完整结果布局但资料不足时，可以提供明确标注的预览控制，在导入前、空白结果、详情展开等布局状态之间切换。预览控制放在独立区域，仅改变展示状态；业务数据区域保持空白，正式用户操作与预览工具分别说明。

解析、保存、分析或刷新等操作需要尚未连接的服务时，说明所需条件并保持对应请求操作不可用。布局查看使用真实页面的模块、字段和标签，业务结果依据实际接口和有效资料取得。

通过现有本地预览能力或项目运行方式打开文件。运行关键操作并检查目标宽度下的 DOM、交互、焦点、换行、溢出和遮挡，读取实际结果。只有用户明确要求时生成截图或进行视觉检查。

Demo 的检查证明预览中的布局与交互。正式业务流程、真实接口、保存和生产页面验证使用 [verification.md](verification.md) 的要求。

Demo、HTML 预览与截图包不提交 Git。用户要求保留时，通过被 Git 忽略的交付目录和文件交付。页面内点击可用于体验，设计反馈以用户在会话中的答复为准。

产物是可运行 HTML、访问方式、可用能力和实际检查结果。用户要求先查看 Demo 时，交付后等待设计反馈；正式修改按照已确认设计和已有授权进行。
