# 正式修改、验证与页面核查

## 实施输入与保留要求

使用当前有效请求、已确认设计、最新文件、现有接口和正式修改授权。正式实施由 [developing](../../developing/SKILL.md) 保存完整目标和剩余工作。

- 修改页面结构、CSS 和 JavaScript，使真实页面符合已确认设计。
- 复用已有图表、导航、表单、输入处理和分析能力，保留用户指定内容。
- 核查控件、事件、请求、数据类型、字段含义、保存行为及异步结果有效性。
- 用户在工作期间修改了文件时，从最新内容继续。
- 确认结构、事件或 CSS 的全部引用后，按授权处理不再使用的内容。

正式页面需要支持从输入或选择到核对、提交、处理、结果及后续操作的完整流程。

## 验证条件与实际结果

使用真实服务、有效账户、实际接口和有效数据。不使用 mock、伪造返回值、跳过失败要求或改变验收条件来取得通过结果。

记录服务地址、账户与数据来源、相关配置、命令、版本或文件状态和实际结果。缺少有效导入资料、账户访问、模型凭据或其他必要条件时，具体记录受影响要求及所需条件，并继续独立且已经授权的工作。

无数据账户的检查覆盖无数据状态；有效数据导入及其结果需要单独验证。请求发送、接口返回与真实模型回答分别取得证据。条件显示区域在对应数据出现时检查；该条件尚未出现的流程保持未验证。

## 完整操作验证

选择与修改范围相符的已有语法、单元、接口和浏览器检查，运行并阅读实际输出。用户操作覆盖：

- 输入或选择、导入、字段核对、异常提示、确认、处理和结果。
- 查看详情、筛选、编辑、保存、撤销、恢复和刷新。
- 弹窗打开与关闭、Escape、键盘可达性和焦点返回。
- 没有数据、有数据、资料不足、处理中和错误状态。
- 图表与指标、数据更新、相关页面和来源状态。
- 桌面、平板、手机及布局断点附近的宽度，正文阅读、横向溢出、遮挡和主要操作可达性。

根据当前功能选择必要组合，覆盖全部适用要求。等待动画达到最终位置后操作控件，布局与标题检查使用实际可见 DOM。检查连续操作和页面切换后的异步结果有效性。

常规验证使用真实 DOM、浏览器操作、网络响应和日志。截图和视觉检查根据用户明确要求执行。

出现异常时，提供触发路径、预期行为、实际观察及证据，使用 [debugging](../../debugging/SKILL.md)。在授权范围内处理得到证据支持的问题，再运行原始复现和受影响检查。改变代码、数据、依赖或配置后，重新执行受影响验证。

## 全部相关页面和入口

依据真实路由、控件、菜单和共用组件建立覆盖清单，检查主页面和相关附加页面。实际执行：

- 导航链接、页面内按钮和菜单跳转。
- 直接访问、刷新、前进和后退。
- 在每个适用页面打开账户设置、资料编辑与共用弹窗。
- 从概览进入明细、依据、模拟、优化或研究页面，再返回来源页面。

核查页面内部的标题、信息层级、文案、条件显示和展开行为，并检查 HTML、CSS 与事件引用。每个确认的问题附位置、触发操作、影响和证据。

覆盖结果分别记录页面与入口、状态、宽度和实际结果。全部相关页面与路径遵循已确认设计，适用的共用交互能够使用。

## 审核、记录和 Git

把设计决定、实际修改、验证证据、未完成要求和当前授权返回 `developing`，使用当前会话或已有 Working Plan 保存。正式修改的 LOG、TODO、最终检查与 commit 按其规则执行。

独立审核按照当前用户授权执行，提供实际文件、有效要求和证据。主代理核查确认的问题并处理；修改后重新验证受影响要求。

commit 前核对文件清单和修改内容，只包含已授权的正式修改。确认 Demo、HTML 预览、截图包和验证中间资料位于 Git 忽略目录。commit 后报告结果；push 需要用户明确授权，单独执行并满足相应审核条件。

## 演示交付

按照用户请求交付：

- 运行中的服务：验证健康状态和页面访问，提供地址及所需登录条件。
- 可浏览 Demo：提供文件或运行方式，说明实际数据来源、可用交互与保存能力。
- 截图包：用户明确要求后，依据页面与状态清单生成截图和目录，检查文件、覆盖范围与压缩包完整性。

使用当前已确认界面，资料通过访问地址或被 Git 忽略的文件目录交付，不提交演示文件。交付说明对应资料实际支持的能力。

## 完成条件

逐项核对当前请求、保留要求、页面和操作范围，以及对应运行证据。完整业务、相关页面和适用检查通过后报告其完成。缺少必要条件的要求明确列为未验证，保持所需验证范围。
