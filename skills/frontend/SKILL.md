# Janus Frontend

## 职责与当前阶段

围绕用户任务理解页面、组织信息、设计交互并取得适用的运行证据。当前请求决定交付阶段：代码阅读、页面审计、布局设计、ASCII 草图、HTML Demo、正式修改、页面核查或演示交付。

直接收到审计或设计请求时，完成所要求的分析与产物。正式实施由 [developing](../developing/SKILL.md) 保存完整目标、执行安排和剩余要求；本技能提供前端方法与阶段结果。已经确认的设计、现有上游产物和用户文件修改作为当前输入。

开始时明确用户任务、目标页面、需要保留的组件与业务规则，以及文件修改、commit、push 和独立审核的授权。只读审计通过会话交付；Demo 授权覆盖预览文件，正式页面修改遵循相应授权。已有授权持续有效，后续请求改变的部分按照新要求执行。

## 按任务进入流程

阅读代码、审计、布局设计、草图或 Demo 时，读取 [audit-and-layout.md](references/audit-and-layout.md)。正式修改、运行验证、全页面核查或演示资料交付时，读取 [verification.md](references/verification.md)。正式实施需要设计依据时，使用当前已确认产物及相应设计 reference。

布局重组依次完成页面理解、元素审计、信息层级和状态设计、ASCII 草图及已授权的 HTML Demo。用户仅要求其中某个阶段时，在该阶段完成交付；明确的局部修改依据已有设计要求实施并验证。已有阶段产物仍适用时，直接使用。

制作任何新的 HTML Demo 前，必须先交付与目标布局一致的 ASCII 文本框草图。草图需要说明模块位置、主次、主要操作和影响布局的状态。根据用户反馈更新草图，再据此制作预览。用户要求先查看草图或 Demo 时，交付该产物并等待反馈；用户已经授权继续时，完成后续工作。

## 必须保留的要求

- 按信息数量、视觉层级、空间布局和操作复杂度审计，逐项说明保留、降级、折叠或建议删除的理由；不确定事项标记为待决策。
- 围绕核心操作和结果使用渐进式披露，保留完整业务能力、用户认可的组件、数据含义和必要状态。
- Demo、HTML 预览和截图包不提交 Git。创建文件前确认允许写入的目录已被 Git 忽略；默认使用目标项目的 `.janus-work/frontend/`，已有合适目录时沿用。系统临时目录不用于本流程。
- 使用真实文件、真实服务、有效账户和有效数据验证。不使用 mock、伪造响应或改变验收要求来取得通过结果。缺少必要条件时，明确记录未验证的要求和条件。
- 完成实现后运行并验证完整用户操作，修复确认的问题并重新验证。页面截图和视觉检查依据用户明确要求执行；常规验证使用实际 DOM、交互、响应和日志。
- 普通界面采用清楚的任务文字，代码 identifier 和适用的专用名词保持英文原名。减少重复说明与防御性文案，保留当前任务需要的错误、状态和来源信息。

## 与 Janus 的协作

- 页面结构、信息主次和交互状态使用本技能的方法。涉及业务含义、功能去留、任务范围、接口含义或验收条件的未决问题，携带当前证据和阶段使用 [brainstorming](../brainstorming/SKILL.md)，得到决定后继续。
- 发现可观察异常时，携带触发操作、预期结果、实际结果及证据使用 [debugging](../debugging/SKILL.md)。诊断或修复后返回受影响的前端步骤，重新执行原始操作和受影响检查。
- 使用其他明确调用的设计技能或现有 PRD 时，保留其适用决定和产物，补充本次任务需要的阶段与验证。对当前操作有影响的矛盾依据当前有效请求处理。
- 嵌入执行任务时，把当前阶段、已确认决定、待决策事项、文件或 Demo 路径、实际修改、验证证据、未完成要求及授权返回 `developing`。使用当前会话或已有 Working Plan 保存交接信息。

## 完成与交付

审计交付元素价值、四类问题、处理理由和待决策事项；设计交付位置、状态、交互和草图；Demo 交付可运行预览与实际检查结果；正式修改交付完整用户流程及真实验证证据；演示资料按请求交付并检查完整性。

完成声明对应当前产物和实际验证范围。缺少数据、凭据或运行条件的要求保持未验证，继续独立且已经授权的工作。

正式修改的审核、项目记录和 commit 使用 `developing` 的规则；独立审核根据当前授权执行。Demo 保持 Git 忽略。commit 完成后报告结果，push 需要用户明确授权并单独执行。
